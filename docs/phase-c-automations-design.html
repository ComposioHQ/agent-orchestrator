Architecture

The daemon owns time. Sessions own execution.

A thin observer supplies cadence. The automation service owns all scheduling decisions and durable state; it delegates actual agent creation to the existing session service.

Scheduling model

Explicit rules, deterministic advancement.

Canonical schedules use RFC-style recurrence rules plus an IANA timezone. Five-field cron is accepted only as input sugar when it maps without changing meaning.

Occurrence algorithm

1
Validate

Exactly one of RRULE or cron; reject ambiguous, invalid, past-only, or faster-than-minute schedules.

2
Materialize

In one transaction, create up to three due run rows using a unique scheduled occurrence.

3
Advance

Move next_run_at beyond “now” even when downtime produced more than the catch-up cap.

4
Dispatch

Lease the oldest pending run only when the automation has no spawning or running work.

Durable run state

Every scheduled occurrence has a queryable record before AO attempts to spawn it.

pending→ spawning→ running→ completed
spawning↘failed
Completion invariant: a run becomes completed only when its linked session is durably marked is_terminated. A failed or unknown runtime probe is never proof that work is dead.
Persistence

Definitions and executions are separate durable facts.

The schema supports auditability, safe retries, and recovery without storing derived display status. A nullable session link makes spawning idempotent across process crashes.

Reliability contract

Failures become inspectable states, not mysteries.

The scheduler provides at-least-once dispatch with application-level idempotency. Recovery is deliberate, bounded, and based on persisted facts.

Transactional claims

Only a leased pending run can spawn, and expired leases are eligible for deterministic recovery.

Idempotent session spawn

The automation run identity is carried into session creation so a restart can find an existing result.

No overlapping runs

Spawning or running work blocks later occurrences, which remain durable instead of disappearing.

Bounded catch-up

At most three missed occurrences are recovered; the schedule always advances beyond the current time.

Timezone correctness

IANA zones preserve local intent across daylight-saving transitions while storage remains UTC.

Privacy-aware errors

Run failures retain bounded diagnostics and structured logs without copying the full user prompt.
