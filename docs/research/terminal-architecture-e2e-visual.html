Terminal architecture · end to end

Where terminal truth lives.

AO’s terminal is not just a canvas. It is a distributed state machine stretched across an agent, tmux, a PTY stream, the network, and a browser renderer.

01 / THE PROBLEM

Three layers can all be “right” and the screen can still be wrong.

Today each viewer receives a fresh tmux attach stream and rebuilds a screen in xterm.js. That delivers local persistence, but every boundary can introduce a different idea of size, history, modes, and repaint timing.

01Agent / TUI

Writes VT sequences inside a tmux pane. Its behavior depends on the pane’s TERM and current grid.

02tmux

Owns the durable Unix process, screen, history, terminal modes, and pane dimensions.

03Attach PTY

One fresh tmux attach per viewer emits handshakes and a non-atomic repaint.

04xterm.js 5.5

Parses the stream again, owns client scrollback, fits the layout, then paints via WebGL or canvas.

↻

Reattach artifacts

A current screen arrives as a timed sequence of redraws, so users can see history fast-forward or stale intermediate frames.

↔

Resize fights

One PTY has one grid. Desktop, web, and phone viewers all measure different grids and can trigger reflow.

⌁

WAN backlog

Raw bytes preserve obsolete animations. A slow viewer can receive every paint instead of jumping to current state.

Aa

Font / GPU drift

Glyph metrics, font loading, DPR, WebGL atlases, and canvas fallback are coupled to session symptoms.

?

Weak attribution

The agent, tmux, attach PTY, transport, parser, and renderer can each plausibly own the same visual bug.

⊞

Platform split

Unix relies on tmux; Windows already has a centralized ConPTY host with a raw replay ring.

Tempting first move
“Replace xterm.js and the regressions go away.”

A new renderer still consumes a per-client attach stream, negotiates another size, reconstructs history from bytes, and inherits Unix/Windows divergence.

The architectural move
Move terminal authority next to the process.

Own the PTY, canonical size, VT state, scrollback, and ordered history once. Make every UI a resumable view of that truth.

02 / THE LANDSCAPE

Use each terminal project for what it is actually good at.

No available project is a complete drop-in answer for AO’s cloud, browser, mobile, multi-client, Unix, and Windows requirements. The right architecture composes a strong core with an AO-owned protocol and client boundary.

Resume the screen you need—not every frame you missed.

THE RESIZE RULE

One grid needs one visible controller.

A PTY cannot be 160×48 for a desktop and 52×22 for a phone at the same time. Make the tradeoff explicit instead of hiding it in “largest socket wins.”

  1. The controller’s measured grid sets canonical PTY dimensions.
  2. Observers crop, pan, or letterbox without resizing the process.
  3. Control transfer changes a visible lease generation atomically.
  4. Phones join read-only and explicitly request takeover.

06 / FEATURE BAR

“Best in class” is a complete interaction contract.

Rendering ANSI is table stakes. Production readiness means local-feeling latency, coherent reattach, search, modern text, accessibility, rich content, and phone behavior all survive the same state model.

01 · LATENCY

Current state wins

No obsolete animation backlog. Measure input → PTY → delta → paint. Predict only verified normal-shell input.

02 · REATTACH

Atomic first frame

Cursor, title, palette, modes, alt screen, links, and mouse state arrive before input is enabled.

03 · HISTORY

Server search

Page logical scrollback, preserve hard/soft wraps, and copy text without padded cells or full-history downloads.

04 · TEXT

Modern input + glyphs

Graphemes, combining marks, fallback, ligatures, CJK IME, emoji, Kitty keyboard, compose, and dead keys.

05 · RICH CONTENT

Links and images

Safe OSC 8 links and quota-controlled Kitty/SIXEL blobs that reconnect by reference, not giant inline replay.

06 · ACCESS

Semantics, not pixels

DOM accessibility mirror, screen-reader updates, contrast, reduced motion, and keyboard-only selection/search.

07 · MOBILE

Touch-native viewing

Long-press selection, touch scroll, pinch font size, safe areas, modifier row, and viewer-first control.

08 · COLLAB

Visible roles

One controller, many observers, presence, explicit takeover, and no surprise resize from a dashboard thumbnail.

09 · DIAGNOSIS

Layer attribution

Generation, sequence, resize lease, parser, font, DPR, and GPU backend—without terminal content in telemetry.

07 / MIGRATION

Now, next, later—with an exit gate at every boundary.

The plan avoids a flag day. Each phase improves the system independently, produces evidence for the next decision, and preserves a known rollback path.

Now · Stabilize

Make failure observable.

Keep tmux and xterm deployable while defining the contracts the new host will inherit.

  • Fixture corpus: output, input, resize, timing, semantic hashes, screenshots
  • Test xterm.js 6 across WebGL/canvas, DPR, fonts, IME, Unicode, and search
  • Add stream generation, replay completion, acknowledgements, and bounded queues
  • Introduce controller/viewer roles and a single resize lease
  • Measure attach-to-stable-frame and input-to-first-paint
GATE · Every regression is reproducible and no observer resizes the PTY.
Next · Establish authority

Ship the Terminal Host.

Move process and state ownership into the workspace without requiring a new renderer.

  • Supervised per-session host with POSIX PTY and ConPTY adapters
  • Pin libghostty-vt behind a narrow AO-owned boundary
  • Shadow-parse current streams and compare fixture state
  • Send one coherent VT snapshot, replay barrier, then live output to xterm
  • Canary new sessions; retain legacy tmux sessions and creation fallback
  • Add bounded logical scrollback and server search
GATE · Atomic reconnect and identical POSIX/Windows protocol fixtures.
Later · Native state

Earn renderer independence.

Let cloud performance and interaction evidence justify a semantic client renderer.

  • Version AO snapshot/delta protocol from observed host behavior
  • Run a hidden state renderer beside xterm and compare hashes
  • Build accessibility, IME, touch, shaping, and mobile into release gates
  • Move images to content-addressed blobs; preserve OSC 133 regions
  • Add guarded Mosh-style prediction for known-safe shell states
  • Graduate web, phone, and Electron independently
GATE · Native clients meet or beat xterm across the full feature bar.
08 / RISKS

The difficult parts are known—and can become gates instead of surprises.

The target trades inherited tmux behavior for deliberate product ownership. These are the questions that must stay visible while the bridge is built.

libghostty-vt API churn

Pin revisions, wrap a tiny surface, keep AO-owned protocol types, and run a golden corpus on every upstream upgrade.

The host crashes while owning the PTY

Use per-session isolation, a supervisor, fault tests, and visible exit reasons. Keep tmux creation fallback until reliability is demonstrated.

Cell width and shaping disagree

The server determines semantic cells and negotiates width-table versions; clients shape inside those cells and report font metrics.

A slow observer exhausts memory

Use a bounded shared journal, per-client credit, delta coalescing, snapshot reset, and disconnection thresholds.

Graphics become a resource attack

Start disabled. Bound decoded bytes, dimensions, image count, storage, hyperlinks, OSC payloads, and retention before allocation.

Accessibility arrives too late

Treat the semantic accessibility tree, keyboard control, contrast, and reduced motion as first-renderer release gates.

Recordings leak secrets

Collect content-free timings by default. Make capture explicit, local-redacted, short-lived, and excluded from ordinary telemetry.

Prediction corrupts TUI input

Require narrow positive safety conditions, visually distinguish predicted cells, reconcile immediately, and disable on any uncertainty.

The recommendation in one line

Move truth before pixels.

Make the workspace Terminal Host authoritative. Use libghostty-vt to avoid reinventing terminal semantics. Keep xterm.js as a reversible client until AO’s state protocol, accessibility, and mobile experience prove a replacement is ready.
