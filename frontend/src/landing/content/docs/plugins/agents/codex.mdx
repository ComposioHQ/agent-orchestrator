---
title: Codex
description: Built-in Terminal UI and native app-server Chat support for the user's Codex installation.
---

AO uses the locally installed `codex` executable and Codex-owned authentication.

```bash
ao agent ls
ao spawn --project my-app --name codex-task --agent codex --mode chat
```

## Interfaces

- **Terminal UI:** runs the native Codex CLI in the session worktree.
- **Chat:** connects to Codex's native app-server protocol and persists the provider conversation identity with the AO session.

Codex supports the same capability-gated Chat/Terminal UI handoff as Claude Code. The AO session and worktree remain stable across a compatible handoff.

AO performs bounded installation and authentication probes before spawn. Use `--skip-agent-check` only to bypass that advisory CLI preflight; daemon validation remains authoritative.

## Profiles

Open **Settings → Agents** to see the identity in the effective `CODEX_HOME`, create isolated profiles, and view their current provider-reported subscription capacity. Sign-in runs through Codex's browser authentication flow. Codex writes and refreshes its own credentials; AO does not parse or expose credential files, tokens, reset credits, or raw provider payloads.

Managed profiles are stored under AO's state directory and remain separate from the existing Codex home. Local Codex tasks can select a profile, and AO pins that exact profile to every later Terminal UI, Chat, restore, switch, and reviewer process for the session.

Capacity is kept only in daemon memory and is updated by bounded reads plus live events from profile-bound Codex Chat sessions. It can be stale or unknown, and is always advisory: a near-limit or exhausted profile remains selectable and never changes the session's immutable binding. AO does not poll, persist usage history, consume reset credits, or automatically switch profiles. Assisted switching arrives in a later phase.
